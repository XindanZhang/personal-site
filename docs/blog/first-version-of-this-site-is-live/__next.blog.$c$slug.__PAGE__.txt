<p>I wanted a place that feels closer to how I actually work: terminal windows, short notes, project logs, bookmarks I still reopen, and blog posts that keep the useful parts of debugging instead of just the polished ending. The old version was enough to start publishing, but this version feels much closer to the shape I wanted.</p>
<h2 id="what-is-here-now">What is here now</h2>
<p>Right now the site has four simple parts:</p>
<ul>
<li><code>blog</code> for notes, writeups, and small technical logs</li>
<li><code>projects</code> for the code and experiments behind the site</li>
<li><code>bookmarks</code> for the few links I still come back to</li>
<li><code>about</code> for the short README version of who I am and what I work on</li>
</ul>
<p>The stack is also different now. The site is built with <code>Next.js</code>, <code>Tailwind CSS</code>, markdown content, and a static export flow that still fits GitHub Pages.</p>
<h2 id="what-i-wanted-from-the-design">What I wanted from the design</h2>
<p>I did not want an editorial landing page or a portfolio full of big cards. I wanted something that feels structured, technical, and a little closer to a shell interface, but still readable enough to use every day.</p>
